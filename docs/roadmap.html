1 · DSP & Audio Suite Done

The Wavelet-class effects chain, shipped across two batches (DSP-a engine + DSP-b UI/platform effects). Binding constraint held throughout: every effect individually toggleable, each with its own independently persisted enable flag — no coupling. In-pipeline processors run in the EQ's double-precision path; reverb/virtualizer attach to the sink-committed audio session.

  • Per-effect state + controller — independently persisted enable/param states; single-applier design, thread-safe
  • Float-through processor chain — EQ emits unclamped float for headroom; encoding restorer owns the 16-bit tail; chain order pinned by test
  • Bass boost — adjustable low-shelf (frequency + gain), in-pipeline
  • Channel balance — attenuate-only per-channel gain, in-pipeline
  • Limiter — soft-knee, instant attack / exponential release, on by default; replaces the old hard clip
  • ReplayGain — zero-dependency FLAC/ID3 tag parser (overflow-hardened) + Tidal playbackinfo gains, routed per track; mode/preamp/fallback UI
  • Reverb — platform PresetReverb (7 presets) via the audio session
  • Virtualizer — platform effect via the audio session, 0–100% strength
  • Sleep timer — presets + “finish this track” phase, live countdown, cancelable
  • Per-effect toggle UI — eight expandable sections on the Equalizer screen, each with its own switch; headphone correction (AutoEq) and the graphic EQ are separate, independently-toggleable stages
Done means: every effect has its own toggle, settings persist/restore independently, regression tests per processor + section goldens, 283 tests green. Reverb/virtualizer audibility is the one thing CI can’t verify — shipped with an on-device checklist.

5 · Crossfade Queued

Real engine work: a second player instance with overlapping playback and gain ramps, coordinated with the queue and the DSP chain. Desktop has it; deliberately sequenced after the DSP suite so the chain architecture is settled first.

  • Dual-player crossfade engine — configurable duration, gapless fallback
  • Settings integration — duration slider, on/off (individually toggleable, per the DSP rule)
Done means: album playback can crossfade smoothly on-device without breaking gapless, queue persistence, or the EQ chain.

6 · Smart Playlists Queued

The largest true gap — a rules engine, not a port. Schema for criteria (genre, year, play count, recency, source…), evaluation against the library, and management UI. Desktop's smart_playlists module is the behavioral spec.

  • Rules schema + Room migration
  • Evaluation engine — with tests mirroring desktop test_smart_playlists.py
  • Builder UI + Collection integration
Done means: a rule-based playlist built on the phone matches what the same rules produce on desktop.
